Why certificate automation stalls on the private key

On the surface the problem is drudgery: creating DNS validation records by hand, downloading files, uploading them to each server and CDN in turn. Validity periods keep shrinking, and one missed renewal puts a security warning in front of your users. Automation solves that part.

What actually stops enterprises is different: automating this means some system holds your private key. A security review asks where the key is stored, who can download it, and whether downloads are logged — and for most platforms the answer is "with us." Procurement stops there.

Kineticlinks hands that decision back: three key modes, including an agent that generates the key inside your own network and never uploads it. Platform-managed keys cannot be downloaded by default — an administrator has to enable it for that account, and every download after that is written to the audit log. The full security write-up is public on the platform, including the parts we have not built yet.

Frequently asked questions

Can the platform see my private key?

That depends which mode you pick. Platform-managed keys are generated and stored encrypted, cannot be downloaded by default, and need an administrator to enable it for that account — after which every download is written to the audit log. With bring-your-own-CSR the key never reaches the platform at all. In agent mode the key is generated by the agent in your own racks and stays on your machine; it is never uploaded.

Which DNS providers can be validated automatically?

Ten at present: GoDaddy, NS1, Namecheap, Cloudflare, AWS Route 53, Tencent DNSPod, Google Cloud DNS, UltraDNS, Constellix and Akamai Edge DNS. The list keeps growing — if yours is not on it you can validate manually, or talk to us about adding it.

Which CDNs can certificates be deployed to?

Seven at present: Apeiro8 CDN, Skycloud (CDNRay), CDNetworks, Alibaba Cloud, Tencent Cloud CDN / EdgeOne, EdgeNext and CDN5. Once deployment finishes the platform connects from several edge nodes to confirm the chain and that the certificate is actually live, rather than just reporting that an API call succeeded.

Can it deploy to servers that are not reachable from the internet?

Yes, using the on-premise agent. One Linux machine runs the agent as a hub and installs certificates over SSH onto the machines you list (nginx, haproxy, Apache). The key is generated on the hub and only ever travels inside your network; the platform cannot see it. Agent packages are signed, so you can verify them with ssh-keygen -Y verify. This feature requires the Enterprise plan.

Who issues the certificate, and will browsers trust it?

Certificates are issued by the GoGetSSL DV CA, chaining up through USERTrust to a publicly trusted Sectigo root. That root ships in the trust stores of every mainstream browser and operating system, so nobody has to install anything.

How does billing work? Is there a monthly fee?

Certificates are priced individually — from US$30/year for a single domain, from US$90/year for a wildcard — drawn from your account balance, with reissues inside the validity period free. Automation is what the subscription buys: Basic is free but includes none of it; Pro at US$29/month adds CDN deployment, DNS validation and edge checks with up to 5 members; Enterprise at US$149/month adds the on-premise agent and unlimited members. New accounts get 14 days of Pro and then fall back to Basic, with nothing charged automatically.
